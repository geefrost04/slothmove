 SlothMove — สรุปโครงโปรเจกต์ + ขั้นตอนการทำข้อมูล (PDF → ข้อความ → HTML)
 อัปเดต: จากโครงสร้าง workspace ใน SlothMove
================================================================================


--------------------------------------------------------------------------------
ส่วนที่ 1 — ประเภทโปรเจกต์และเทคนิค
--------------------------------------------------------------------------------

• เว็บสแตติกเป็นหลัก: ไฟล์ HTML เปิดจากเบราว์เซอร์ได้โดยตรง
• ใช้ Tailwind CDN + ฟอนต์ Google (Kanit, Sarabun)
• ไม่พบ package.json ในราก — เหมาะกับการ deploy แบบ static hosting


--------------------------------------------------------------------------------
ส่วนที่ 2 — โครงโฟลเดอร์หลัก (ราก SlothMove)
--------------------------------------------------------------------------------

index.html
  หน้าแรกของเว็บ (แบรนด์ SlothMove, SEO/OG, ลิงก์ไปแต่ละสายเรียน)

Page/
Page/source/
  OPSD/     → คอร์สสายสำนักงานปลัดกระทรวงกลาโหม (OPSD)
  Industry/ → คอร์สสาย สป.อก./กระทรวงอุตสาหกรรม
  PAB/      → คอร์สปภ. (แบ่งส่วนที่ 1 / ส่วนที่ 2)

  ภายในแต่ละสายโดยทั่วไปประกอบด้วย:
  - หน้ารวมวิชา (เช่น indexopsd.html, indexindustry.html, indexPAB.html)
  - หน้าบทเรียน (.html ตามวิชา)
  - หน้าควิซ (ชื่อประมาณ Quiz_*.html)
  - leaderboard.html — กระดานคะแนน

pic/
  รูปใช้บนเว็บ เช่น โลโก้ (ปภ., OPSD, อุตสาหกรรม), QR พร้อมเพย์, mascot

data ปภ/
  จัดเก็บ/โฟลเดอร์ความรู้ประกอบปภ. (โครงย่อยเป็นหมวดภาษาไทย)
  เหมาะเป็นแหล่งอ้างอิงระหว่างทำสรุปและข้อสอบ

supabase_sql/
  สคริปต์ SQL ที่เกี่ยวกับฐานข้อมูล เช่น column คะแนน/แผนก (ใช้กับ leaderboard)


--------------------------------------------------------------------------------

   - indexopsd.html — ประตูเข้าคอร์ส
   - บทเรียน + Quiz_*.html หลายวิชา (อังกฤษ, ความสามารถทั่วไป, สารบรรณ,
     ความมั่นคง, ข้อมูลข่าวสาร, จริยธรรม ฯลฯ)

   - indexindustry.html — ประตูเข้าคอร์ส

   - Quiz_Industry_mixed_150.html — ควิซผสม

3) PAB — ปภ. (Page/source/PAB/)
   - indexPAB.html — ประตูเข้าคอร์ส แบ่งส่วนที่ 1 และ ส่วนที่ 2 (พับ/ขยาย)
   - บทเรียนและ Quiz_* จำนวนมากตาม Curriculum ปภ.


--------------------------------------------------------------------------------
ส่วนที่ 4 — ขั้นตอนการทำข้อมูล (PDF → สกัดข้อความ → หน้า HTML)
--------------------------------------------------------------------------------

เป้าหมายของ pipeline คือเปลี่ยนเอกสารต้นฉบับ (PDF) ให้กลายเป็นข้อความที่จัดได้
จากนั้นนำไปเขียนหรือ generate เป็นไฟล์ HTML ใน Page/source/<สาย>/ ให้หนักัยากับ
ประเภทหน้า: “บทเรียน”, “ควิซ”, และอัปเดตหน้ารวมวิชา

────────────────────────────────────────
ขั้นที่ A — รวบรวมและเตรียม PDF
────────────────────────────────────────
1. เลือกชุดเอกสาร (กฎหมาย, ระเบียบ, คู่มือ หรือข้อสอบ/แนวข้อสอบ) ให้ชัดว่าเป็น
   คอร์ส OPSD / Industry / PAB และวิชาใด
2. จัดเก็บ PDF เป็นโครงที่ trace ได้ เช่น:
   data_raw/pdf/<สาย>/<รหัสหรือชื่อวิชา>/<ชื่อไฟล์แหล่งที่มา.pdf>
   หรือต่อยอดโครงภายใน data ปภ/ ให้เข้ากับทีม
3. เช็กลิขสิทธิ์/ขอบเขตการเผยแพร่เนื้อหาที่นำเข้ามาสรุปบนสาธารณะ


────────────────────────────────────────
ขั้นที่ B — นำ PDF เข้าและสกัดเป็น text
────────────────────────────────────────
1. แบ่งประเภท PDF:
   - ข้อความเลือกได้ (เลือกเมาส์ทับได้): ใช้เครื่องมือสกัด text โดยตรง
     (เช่น pdftotext, Python: pypdf / pdfplumber)
   - สแกนเป็นภาพ: ต้องใช้ OCR ก่อน แล้วค่อยได้ไฟล์ข้อความ
2. บันทึกผลลัพธ์เป็นไฟล์เดียวหรือแยกบท เช่น:
   <วิชา>_extracted_raw.txt หรือ .md
3. เมตาดาทาที่ควรเก็บ: ชื่อไฟล์ PDF เดิม, วันที่สกัด, รุ่น/เล่มของเอกสาร (กฎที่แก้ไขแล้วฯลฯ)


────────────────────────────────────────
ขั้นที่ C — ทำความสะอาดและจัดโครงข้อความ
────────────────────────────────────────
1. ลบ noise จากการสกัด เช่น เลขหน้าซ้ำหน้า, header/footer จาก PDF
2. จัดเป็น outline หมวด/ข้อ มาตรา/ประเด็น ให้สอดคล้องกับหัวเรื่องบนหน้า HTML
3. (ถ้ามีทีม) ทำเครื่องหมายจุดที่มักออกข้อสอบ เพื่อใช้ตอนสร้างข้อควิซ


────────────────────────────────────────
ขั้นที่ D — สร้าง / แก้หน้า HTML
────────────────────────────────────────

บทเรียน (Lesson)
1. คัดลอกเทมเพลตจากหน้าเดียวกันในสายนั้นที่ใกล้เคียงกับประเภทเนื้อหาใหม่
2. ใส่ meta / หัวเรื่อง / breadcrumb และเนื้อหาเป็น h2,h3 และรายการ
3. เช็ก path ภาพ (มักเป็น ../../../pic/ หรือ pic/ ตามระดับโฟลเดอร์)
4. อัปเดตการ์ดลิงก์ในหน้ารวม (index*.html)

ควิซ (Quiz_*.html)
1. แยกจากข้อความที่จัดแล้วเป็น คำถาม / ตัวเลือก / เฉลย
   (ภายใน repo โครงควิซอาจอยู่ใน HTML เดียว — ควรให้ฟอร์มตัวเลือกสอดคล้องกับ
    ควิซอื่นในสายเดียวกันและระบบบันทึกคะแนนถ้ามี)
2. ตั้งชื่อไฟล์ให้เข้ากับแนวเดิมของสายนั้น
3. ลิงก์จากหน้าบทเรียนหรือหน้ารวม

กระดานคะแนน
1. เมื่อเพิ่มควิซใหม่ ตรวจว่า leaderboard.html และฟิลด์ใน Supabase
   ผูกด้วย category/แผนกตามที่ออกแบบใน supabase_sql/


────────────────────────────────────────
ขั้นที่ E — ทดสอบและ deploy
────────────────────────────────────────
1. เปิด HTML ในเบราว์เซอร์ เช็กลิงก์เมนู และลิงก์ไฟล์ภาพ
2. ทำลำดับวนใช้งาน: หน้ารวม → บทเรียน → ควิซ → กลับ
3. อัปโหลดสแตติกครบชุด: index.html + Page/** + pic/** และไฟล์ที่อ้างอิงจาก root


--------------------------------------------------------------------------------
ส่วนที่ 5 — เส้นทางเก็บงานใน repo (ข้อแนะนำไม่บังคับ)
--------------------------------------------------------------------------------

• PDF ต้นฉบับ     → data_raw/ หรือโฟลเดอร์ย่อยใต้ data ปภ/
• ข้อความหลังสกัด → .txt / .md คู่ชื่อวิชา และคู่เล่มของเอกสาร
• เว็บที่เผยแพร่   → Page/source/<สาย>/<ไฟล์>.html และ Quiz_*.html
